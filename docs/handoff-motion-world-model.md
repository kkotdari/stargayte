## 2. 아키텍처 지도 (확정 사실, 직접 확인함)

데이터 흐름: **리플레이 명령 파싱 → v2 개체 트랙(ents) → 자취 합성(entWalks) →
프레임 위치(posAt + 교전 보정) → 표시 스무딩(drawPosRef EMA) → 그리기**.

### 2-1. 파서/개체 층 — `src/utils/replayUnits.ts` (2,236줄)

- `pushEv`(458줄): 같은 f·근접 좌표 중복은 합친다(463줄).
- **f-코드 (확인된 것)**: 0=이동 클릭(815·846·858줄), 1=건물 관련 앵커(899줄),
  2=건설 앵커(541·553·701줄), 3=?(760줄), 4=랠리(**x=-1**, 627줄), 5=착륙?(749줄),
  6=?(752줄), **7=어택 명령**(856줄), 10=수리/힐(852줄), 12=탑승(819줄),
  13=하차(372줄), 14/15=클로킹 켬/끔(712줄), 16=스팀(756줄).
- **핵심 확정 사실**: 856줄 `else if (isAtkOrder) { life.ev.push([sec, pos.x,

- 건물 개체: `life.bld`(451·455·551줄), 태그 재활용은 `lifeOf`/`done` 순환으로

  ev에 f=2|5 존재`를 요구 — **게임 시작 시 이미 있던 본진 건물이 이 조건을
  충족하는지가 미검증**(§4-A).

### 2-2. 자취 합성 — `src/components/replay/ReplayMotionPlayer.tsx`

- `entWalks` 메모(6440줄~): ents → 걷는 개체 목록.
  - 걸음 점 필터(6493줄 근처): `if (v[1] < 0 || v[3] === 4) continue;` —
    **f=7(어택)도 걸음 점이 된다**(f=0·7은 행렬 시차 + 해바라기 나선 대형 보정).
  - `atkAt`(6581줄): `ev.filter(v => v[3] === 7).map(v => [v[0], v[4] ?? 0])`.
  - 출생 보정: 첫 증거가 늦고 멀면 가장 가까운 제 홀에서 출발점을 심는다.
- `posAt`(5537-5600줄): 점 사이 선형(지상은 베지어 굽힘) 보간.
  - `LERP_MAX_GAP_SEC` 초과 침묵: 앞 점에 머물다 도착 직전 `거리/BRIDGE_WALK_SPEED`
    초만 걸어서 잇는다.
  - 속도 상한: `GLIDE_MAX_SPEED` 초과·`BRIDGE_MAX_SPEED` 이하 → 전 구간 걸어 잇기,
    그보다 빠름 → 앞 점에 머묾(**다음 구간으로 넘어가는 순간 위치가 점프한다** —
    표시층 EMA가 흡수).
  - **의미론 주의**: 점 `[s1, x1, y1]`은 "s1 시각의 클릭 목적지"인데 보간은 s1에
    x1·y1 **도착**으로 그린다 — 명령 시각에 이미 도착해 있는 셈(모델의 근본 어림).

### 2-3. 교전/표적 층 — 같은 파일

- 상수: `ENGAGE_SIGHT_TILES = 9`(5524줄), `ENGAGE_SKIP`(5527줄),
  `MELEE_UNITS`(5533줄, c4a7fcca가 추가).
- `bldTagSpots`(5845줄 근처, c4a7fcca 추가): 건물 태그 → 자리 색인.
- `entPosByTag`(6627줄 근처): 유닛 + 방어건물 + (c4a7fcca) 일반 건물(`bld: true`).
  일반 건물은 **교전 유발 목록(engageFoes)에는 안 들어간다** — 어택이 태그를
  찍었을 때만 표적.
- 개체 렌더 루프의 교전 블록(8665-8740줄 근처) — **현행 모델의 심장**:
  1. `walkDelay = engageDelayRef[key]` — 교전으로 멈춘 시간만큼 걸음 시계를 미룸.
     `rawPos = posAt(rp, t - walkDelay)`.
  2. `foe = nearestFoe(...)` 후 `atkAt`를 **역순으로 최신 1건만** 보고, 태그가
     entPosByTag에 있고 적팀이며 창(유닛 12초/건물 45초) 안이고 거리 ≤ 9×1.6이면
     foe 교체. (`break`는 최신 1건 검사 후 무조건.)
  3. `fighting = canFight && foe.bd <= 9×(재진입 1.3)`.
  4. fighting이면 `engageHoldRef`의 `base{x,y,t0,tLast}`에 **정지** —
     `mem && t >= mem.t0 && t - mem.tLast < 2.5`면 유지, 아니면 **rawPos로 재생성**.
     표시 위치 = `base + 표적 방향 × pull`.
     - 원거리: `pull = min(2.5, gap - 2.2)`.
     - 근접(c4a7fcca): `pull = min(gap - stopR, 2.5 + (t - base.t0) × 2.6)`,
       stopR = 유닛 1.1 / 건물 2.0.
  5. fighting이 꺼지면: 정지 시간(0.4초 초과분)을 `engageDelayRef.delay`에 **누적**
     하고 hold 삭제 → 이후 rawPos가 그만큼 과거로 밀린다.

### 2-4. 표시 스무딩

- `drawPosRef` EMA(비율 6/s) + 활강 상한 9타일/s, 되감기·1.5초 초과 갭에서만 리셋.
  (정확한 줄은 `drawPosRef` grep.)

## 3. 근본 원인 가설 — 우선순위 순 (검증 방법 포함)

**H1. 교전 정지·걸음 지연의 구조적 미도착 (유력)** — fighting이 켜지면 표시
위치가 base(교전 시작 순간의 자리)에 **박제**되고, 꺼질 때마다 정지 시간이
walkDelay로 누적돼 rawPos 자체가 **점점 과거로** 밀린다. 해처리 앞 난전처럼
fighting이 오래·반복되면, f=7 목적지 점이 있어도 걸음 시계가 영영 그 점에
도달하지 못한다 → "멀리 서서 싸우는 척". *검증*: 교전 반복 시나리오에서
walkDelay 증가량과 rawPos 위치를 손으로 추적(§4-C).

**H2. base·램프 리셋 (유력, H1의 악화 인자)** — 근접 램프 `2.5+(t-t0)×2.6`의
t0는 base 재생성 때마다 리셋된다. base는 `t - tLast >= 2.5`면 재생성되는데,
tLast는 **그 개체가 fighting 상태로 렌더링된 프레임에만** 갱신된다. 뷰포트
컬링(CULL=160, 화면 밖 개체는 루프 스킵)·히스테리시스 깜빡임·일시정지 뒤에는
2.5초가 훌쩍 지나 있어 램프가 2.5타일에서 무한 재시작한다. *검증*: 컬링 경로가
교전 블록을 건너뛰는지 코드로 확인 + 줌아웃/줌인 시나리오.

**H3. 시야 게이트 (구조 결함)** — 접근(당김)은 `foe.bd ≤ 9(×1.3)`일 때만 시작.
9타일 밖에서 어택 찍힌 유닛은 f=7 목적지 보간이 데려다줄 때까지 접근이 없고,
H1·H2가 보간 도착을 막으면 영영 시작되지 않는다.

**H4. 표적 해석 실패 (미검증)** — (a) 최신 어택 1건만 보는 `break` 규칙이 어택땅
(태그 0)에 가려 직전의 태그 어택을 무시. (b) 본진 해처리 등 시작 건물이
`bldTagSpots` 조건(e.t>0, f=2|5 ev)을 못 채워 표적 지도에 없음. (c) 파서
`hostileClick` 판정이 새서 태그가 0으로 기록. *검증*: §4-A.

**H5. 어택 클릭에 pos가 없는 경로 (미검증·가능성 낮음)** — 856줄은 `if (pos &&
!life.bld)` 안이다. 태그 어택인데 pos가 null이면 f=7 자체가 안 남는다. 파서의
클릭 레코드(`src/utils/replayParser.ts` 135·917-919줄 근처)에서 태그 표적 명령의
pos 유무를 확인하라.

## 5. 해결 방향 (기획서의 뼈대 — 조사 결과로 다듬어 확정할 것)

현행 "시야 안에서만, 정지점에서 당기는 오프셋" 모델을 버리고, **개체별 지속
운동층(순방향 적분)** 으로 바꾼다:

1. 개체별 `simPos` ref(키: 엔트 인덱스 고정 키). 매 프레임 `dt`만큼
   현 simPos → 목표점으로 걸음 속도로 이동. 목표점 우선순위:
   ① 유효한 어택 표적(태그 해석 성공, 창 안) — **거리 무관**(시야 게이트 제거),
   ② 자취(rp)의 다음 미도달 점, ③ 현 rawPos.
2. 정지 반경: 유닛 표적 1.1타일(근접)/사거리(원거리), 건물 표적은 고정 2.0이
   아니라 **발자국 절반 + 0.5**(해처리 4×3이면 x2.5/y2.0) — 축별로.
3. walkDelay·engageHold 정지 개념 폐지(또는 이펙트 전용으로 격하): 시야는
   전투 이펙트(트레이서·불꽃) 트리거로만 쓰고 이동은 막지 않는다.
4. 리셋 규칙은 drawPosRef와 동일(되감기·1.5초 초과 점프 시 posAt로 스냅).
   컬링돼 스킵된 개체는 복귀 프레임에 "경과 시간 × 속도"만큼 따라잡되
   9타일/s 활강 상한은 표시층에 그대로 둔다(순간이동 금지 원칙).
5. 파서 쪽 결함(H4b·H5)이 확정되면 파서 수정이 우선이다 — 단, 분석 산출물
   포맷이 바뀌면 재분석 필요 여부를 반드시 명시하라(渲染만의 변경이면 기존
   게임에 바로 반영, ents 포맷 변경이면 제어판 재분석 필요).

  표적 사망 후 재표적, (e) 수동 검증 체크리스트(질럿-해처리 원거리 어택 장면
  포함), (f) 성능 주의(개체 수백 × 매 프레임 — 할당 최소화).
- 기존 원칙 유지: **순간이동 무조건 금지**, 원거리는 멀리서 쏘는 게 제 모습,
  건물이 보이기만 해서 싸움이 시작되면 안 됨.

## 7. 증상 재현 참고

로컬에 .rep 샘플은 없다. 검증은 `npm run dev` 후 실제 게임 상세의 연속 재생에서
사용자가 언급한 "질럿이 해처리 부수는 장면"으로 한다(사용자에게 게임 링크를
물어봐도 된다). 빌드 통과 + 논리 검증까지가 이 세션의 몫이고, 화면 확인은
사용자와의 핑퐁으로 진행한다.
